Quick Start Guide

Learn how to use Daygle Mail Archiver to fetch, store, and manage your emails.

  1. Set up a Fetch Account: Go to Fetch Accounts and add a new email account (IMAP, Gmail, or Office 365)
  2. Enable the account: Ensure the “Enabled” checkbox is selected
  3. Start the worker: The worker will automatically fetch emails based on the poll interval
  4. View your emails: Navigate to the Emails page to browse and search archived emails
Adding IMAP Accounts
  1. Go to Fetch Accounts and click "Add Fetch Account"
  2. Select "IMAP" as the account type
  3. Enter your IMAP server details (host, port, username, password, SSL)
  4. Set the poll interval (how often to check for new emails)
  5. Click "Create Account" to save
  6. Use the "Test" button on the accounts list to verify the connection
Adding Gmail API Accounts
  1. Create a Google Cloud project and enable Gmail API
  2. Create OAuth 2.0 credentials (Client ID and Client Secret)
  3. Go to Fetch Accounts, click "Add Fetch Account", and select "Gmail API"
  4. Enter your OAuth Client ID and Client Secret, then click "Create Account"
  5. Open the account for editing — the Redirect URI (e.g. http://your-domain/oauth/gmail/callback/{account_id}) is displayed in the OAuth Configuration section
  6. In Google Cloud Console: add the Redirect URI to Authorised redirect URIs and save
  7. Return to the edit form and click "Authorise" to complete the OAuth flow
Adding Office 365 Accounts
  1. Register an app in Azure AD / Microsoft 365 Admin Center
  2. Add Mail.Read and offline_access permissions and create a client secret
  3. Go to Fetch Accounts, click "Add Fetch Account", and select "Office 365 API"
  4. Enter your OAuth Client ID and Client Secret, then click "Create Account"
  5. Open the account for editing — the Redirect URI (e.g. http://your-domain/oauth/o365/callback/{account_id}) is displayed in the OAuth Configuration section
  6. In Azure AD: Authentication → Add a platform → Web → paste the Redirect URI and save
  7. Return to the edit form and click "Authorise" to complete the Microsoft authorisation flow
Managing Emails

Viewing Emails: Navigate to the Emails page to see all archived emails. You can search, filter by folder, view full content, and download raw .eml files (requires download_eml permission).

Deleting Emails: Click the delete button next to an email for individual deletion, or use bulk delete (requires delete_emails permission).

Email Verification: Each archived email has a cryptographic signature (SHA256 hash) for integrity verification. Click "Verify" when viewing an email to check if it has been modified since archiving.

Warning: Deletions are permanent and cannot be undone. Users without the required permissions cannot delete emails or download .eml files.
Import/Export

Use the Import/Export page to import and export email archives.

Import: Upload .eml, .mbox, .mbx, or ZIP files. Requires import_emails permission.

Export: Export filtered or all emails as ZIP or MBOX. Requires export_emails permission.

Permissions: Import and export actions are permission‑gated.

Troubleshooting

Connection Issues: Use the Test button on fetch accounts, verify SSL/TLS settings, and check firewall rules.

OAuth Issues: Ensure redirect URIs match exactly and re‑authorise the account.

No Emails Being Fetched: Ensure the account is enabled and the worker is running.

Account Lockout: After too many failed logins, accounts temporarily lock. Use “Forgot Password” to unlock.

Permission Restrictions: If you cannot delete emails or download .eml files, you may not have the required permissions.

Performance Issues: Reduce poll interval or enable retention cleanup.

Email Deletion Behaviour

When “Delete Email After Processing” is enabled, emails are removed from the mail server after archiving:

  • IMAP: Mark as deleted or permanently expunge
  • Gmail: Moves to Trash (30‑day recovery)
  • Office 365: Moves to Deleted Items
Warning: Permanent expunge is irreversible.

Quarantine Management

The quarantine system isolates potentially harmful emails detected by antivirus scanning.

Viewing Quarantined Emails:

  • Navigate to the Quarantine page
  • View details, sender, subject, and quarantine reason
  • Search and filter quarantined emails

Actions (permission‑gated):

  • Release: Move the email back to the archive (quarantine_release)
  • Delete: Permanently remove (quarantine_delete)
  • Delete from Server: Remove from IMAP/Gmail/O365 (quarantine_delete_server)
Caution: Only release emails if you are certain they are safe.
Email Integrity & Verification

Every archived email includes a cryptographic signature (SHA256 hash) to ensure data integrity and detect tampering.

How It Works:

  • When an email is archived, a SHA256 signature is computed and stored
  • The signature is based on the raw email content (RFC822 format)
  • Click "Verify" when viewing an email to check its integrity
  • Verification recomputes the signature and compares it to the stored value

Verification Results:

  • Valid: Email has not been modified since archiving
  • Invalid: Email content has been altered (indicates potential tampering)
  • Missing Signature: Email was archived before integrity checks were implemented
Security: Email signatures provide tamper detection but not encryption. For encrypted storage, enable quarantine encryption for virus-infected emails.

Alert Management

Antivirus Integration

Daygle Mail Archiver integrates with ClamAV to automatically scan incoming emails for malware and viruses.

How It Works:

  • Each email is scanned by ClamAV before being archived
  • Infected emails are automatically quarantined
  • Clean emails proceed to normal archiving
  • Scan results are logged for audit purposes

Configuration:

  • ClamAV must be running and accessible to the worker process
  • Configure ClamAV host and port in Global Settings → Virus Scanning (ClamAV)
  • Quarantined emails are retained for 90 days by default
  • Quarantine data can be encrypted with a dedicated key
Note: Check the AV Stats report for scan statistics and performance metrics.

Backup and Restore

Protect your email archive with the built-in backup and restore script. Backups include both the database and the configuration file containing encryption keys.

Creating a Backup:

cd /opt/daygle-mail-archiver
./backup_restore.sh backup

This creates a timestamped backup file in ./backups/ (or a custom directory) containing the PostgreSQL dump and configuration file.

Listing Backups:

./backup_restore.sh list

Restoring a Backup:

./backup_restore.sh restore backup_file.tar.gz

After restoring, restart services with docker compose restart.

Deleting Old Backups:

./backup_restore.sh delete backup_file.tar.gz
Security Warning: Store backups securely - they contain all email data, encryption keys, and credentials.
System Updates

System updates are managed via the command-line update script. The web-based update checker has been removed in favor of this more reliable CLI approach.

Checking for Updates:

cd /opt/daygle-mail-archiver
./update.sh --check

Updating the System:

./update.sh

This will interactively guide you through the update process.

Unattended Update:

./update.sh --force
Important: Always create a backup before updating using ./backup_restore.sh backup. The update script does not automatically back up your database.
